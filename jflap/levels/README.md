# JFLAP level files

Every level's reference machine is a real JFLAP `.jff` file in this folder. The game loads them to verify what players build.

| File | Used for |
|---|---|
| `R1…R6_reference.jff`, `N1…N4_reference.jff` | finite-automaton references (R4/N4 also have a public blueprint file: `R4_blueprint.jff`, N4's blueprint is its reference NFA) |
| `C1_reference.jff`, `C2_reference.jff` | maintenance-contract (policy v2) references |
| `R5_round{1,2,3}_{A…F}.jff` | the six Twin-Gate machines |
| `G1…G3_reference.jff` | grammar oracles; `G4_given.jff` (ambiguous) and `G4_reference.jff` (unambiguous) |
| `P1…P3_reference.jff` | pushdown-automaton oracles |
| `T1…T3_reference.jff` | Turing-machine oracles (T1 complement, T2 increment, T3 aⁿbⁿ decider) |
| `V1_machineA…E.jff` | the five Void-Zone machines |

| `<Slot>_<variant>_<role>.jff` (129 files) | the extra challenge variants of every mission (see `js/game/variants.js`); generated by `node tools/seed-variants.js`, then edit freely in JFLAP |

**Edit workflow:** open a file in JFLAP → change it → save over the same name → run `node tools/build-levels.js` (packs the files into `js/game/jflap_levels.js` so the game also works by double-click) → reload the game. `npm test` fails if the packed bundle is out of date or a file no longer matches its level.

How the game uses them: finite automata are compared with the player's machine by product-automaton equivalence; grammar/PDA/TM files act as the oracle for hidden tests and bounded verification.
