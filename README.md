# Automata Metaverse

A game-based learning world for **Formal Languages & Automata Theory**. Gates are DFAs, mazes are NFAs, forests are grammars, factories run stacks, labs run Turing tapes, and the Void asks what can never be decided. Players build machines, a real verification engine proves (or refutes) them, verified machines go to a **Machine Archive**, and can be **deployed** into world objects.

No build step, no dependencies, no internet needed (fonts are bundled).

## How to run

Pick any one:

1. **Double-click `index.html`** (Chrome, Edge, Firefox, Safari). Works straight from the folder.
2. **Local server (recommended for sharing):** `node serve.js` (or `npm start`) → open http://localhost:8080
   (any port: `node serve.js 3000`)
3. **Python alternative:** `python3 -m http.server 8080` in this folder → open http://localhost:8080

Run the automated tests (Node 16+):

```
npm test          # 56 formal + 89 game + 20 JFLAP-tool + 32 level-file tests
```

Progress saves automatically in the browser (localStorage). Profile → Export/Import save moves it between machines.
**Evaluators:** tick *Demo mode* on the title screen (or Profile → Settings) to unlock every region and mission.

## What is inside

| Region | Concept | Missions |
|---|---|---|
| Regular City | DFA, minimization, equivalence | R1–R6 (+ Gate/Vending policy-v2 contracts) |
| Nondeterministic District | NFA, ε-NFA, subset construction | N1–N4 |
| Grammar Forest | CFG, parse trees, ambiguity, CNF | G1–G4 |
| Stack Factory | PDA with visible stack | P1–P3 |
| Turing Lab | Turing machines on a visible tape | T1–T3 |
| Void Zone | Halting problem, undecidability | V1–V2 |

22 missions + 2 maintenance contracts. Plus: Central Hub world map, Machine Archive (verify, compare, combine, rename, delete, deploy, export), Sandbox Lab, 14 achievements, XP / levels / ranks, profile with radar chart and analytics, accessibility settings, JFLAP `.jff` import/export.

### The formal engine (real algorithms, `js/formal/`)
- **FA:** clone-frame NFA/ε-NFA simulation (split, ε-portal, merge, dead clones), ε-closure, subset construction with table, completion, reachability, Moore minimization with rounds, product construction (AND/OR/XOR/DIFF), complement, shortest-counterexample equivalence via product BFS.
- **CFG:** parser, CYK membership, all parse trees (ambiguity), leftmost derivation, CNF conversion with a teaching log (ε/unit/useless removal, binarisation), ambiguity search, bounded language checking.
- **PDA:** configuration BFS, final-state and empty-stack acceptance, underflow detection, determinism check.
- **TM:** deterministic simulation, step limit, exact-configuration loop detection (Brent).
- **JFLAP:** `.jff` export/import for FA, PDA, Turing and grammar (`jflap-samples/` has ready examples).
- **JFLAP Workbench (☕ JFLAP tab, `js/formal/jflap_tools.js`):** JFLAP's own tools implemented natively — regular expression → ε-NFA (Thompson), ε-NFA → NFA, FA → regular expression (state elimination), CFG → PDA, LL(1) FIRST/FOLLOW/parse table with step-by-step parsing, and Multiple Run over any machine type.
- **Real JFLAP bridge:** put `JFLAP.jar` in `jflap/` (download from jflap.org — its licence forbids bundling), install Java, start with `node serve.js`; every “☕ Open in real JFLAP” button then launches the real program with that machine loaded. Without the jar it downloads the `.jff` instead.

### Different challenges every time (challenge variants)
The 22 missions keep their place and order, but each slot owns a **pool of 4–7 different challenges** (113 in total, e.g. R1 can be “even number of 0s”, “1s mod 3”, …; N3 “2nd/3rd/4th symbol from the end”; G4 “dangling else”; T2 “decrement”; V1 different Void machines; V2 different questions).
* Every time the game loads (every new player visit) one variant per slot is rolled — seeded, and never the same as the previous visit's variant for that slot.
* `index.html?seed=abc` reproduces a session exactly; `index.html?classic` (or Profile → *Different challenges every visit* off) pins the original challenges, which is handy for scripted demos.
* On a mission, **🎲 Different challenge** swaps just that mission. Profile shows this visit's set and can re-roll all.
* Each variant has its own real JFLAP reference file (`jflap/levels/<Slot>_<variant>_<role>.jff`, 129 files, generated by `node tools/seed-variants.js`) and an independent JavaScript predicate; `tests/variants.test.js` checks every variant (355 tests).
* Progress/score is per mission slot (best across variants); drafts and archive machines are per variant; a deployed machine keeps the policy of the variant it was built for. Maintenance contracts C1/C2 are fixed.

### JFLAP files are the level logic
Every level's reference machine is a real JFLAP `.jff` file in `jflap/levels/` (34 files — see `jflap/levels/README.md`). The game loads them (packed into `js/game/jflap_levels.js` by `node tools/build-levels.js`) and verifies players against them. Open any of them in JFLAP, edit, save, re-pack. The ☕ JFLAP → *Level files* tab lists them all with ⬇ / ☕ Open-in-JFLAP buttons (reference files unlock after you finish the level, or in demo mode).

### Verification honesty
Finite automata are verified **exactly** (product-automaton equivalence — proven for every string). CFG / PDA / TM equivalence is undecidable, so those are verified **up to a stated string-length bound** plus a hidden test suite; the game says so, and the Void Zone teaches why.

### Scoring (blueprint §7)
Per mission (scaled to its max): correctness 500 · efficiency 150 · query efficiency 100 · no hints 100 · speed 50 · optional objective 100. A wrong machine scores **0**. World score = sum of best mission scores; overall = sum of worlds (max 14,300, matching the blueprint's example) + contract bonuses. The blueprint listed both a weights table and a points table that disagree; the points table (sums to 1000) is implemented.

## Project layout
```

js/ui/                graph editor, grammar editor, simulators, lenses, screens
js/app.js             router + HUD + boot
tests/                formal.test.js, game.test.js, solutions.js (test-only answers)
docs/                 TRACEABILITY.md, DEMO_SCRIPT.md
jflap-samples/        .jff files to open in JFLAP
```

## Controls
Double-click canvas = add state · double-click state = toggle accepting · Transition mode or Shift-drag = connect · Delete mode removes · δ shows the transition table · ⬇/⬆ .jff = JFLAP bridge. Grammars: one rule per line, `S -> aSb | ε`, uppercase = nonterminal.
